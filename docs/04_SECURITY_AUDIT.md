## 2. Detailed Vulnerability Breakdown

### 2.1 Critical Vulnerability 1: Public Read/Write on `public.admin_users`
- **Source**: [`supabase/admin_users_setup.sql`](file:///c:/Users/VARUN%20THEJ/OneDrive/Desktop/Rodhe/supabase/admin_users_setup.sql), lines 24–34.
- **SQL Code**:
  ```sql
  CREATE POLICY "Public Read Admin Users" ON public.admin_users
      FOR SELECT USING (true);

  CREATE POLICY "Public Update Admin Users Password" ON public.admin_users
      FOR UPDATE USING (true) WITH CHECK (true);

  CREATE POLICY "Public Insert Admin Users" ON public.admin_users
      FOR INSERT WITH CHECK (true);
  ```
- **Exploit Scenario**:
  Because the public publishable anon key is exposed in the frontend bundle, any malicious actor on the internet can open the browser console and run:
  ```javascript
  const { data } = await supabase.from('admin_users').select('*');
  console.log(data); // Dumps all admin usernames, emails, and passwords!
  ```
  Furthermore, anyone can anonymously execute an `UPDATE` on `admin_users` to change the admin password, or `INSERT` new admin users with the `super_admin` role!

### 2.2 Critical Vulnerability 2: Plaintext Password Storage
- **Source**: [`supabase/admin_users_setup.sql`](file:///c:/Users/VARUN%20THEJ/OneDrive/Desktop/Rodhe/supabase/admin_users_setup.sql), lines 39–43.
- **Code**:
  ```sql
  INSERT INTO public.admin_users (username, email, password_hash, role)
  VALUES ('rodhe', 'rodhe@rodhe.in', 'rodhe@admin', 'super_admin');
  ```
- **Finding**: Despite the column name being `password_hash`, the value stored is the raw plaintext password `rodhe@admin`. No salt, bcrypt, argon2, or PBKDF2 hashing is applied.

### 2.3 Critical Vulnerability 3: Unauthenticated Password Reset
- **Source**: [`src/services/authService.js`](file:///c:/Users/VARUN%20THEJ/OneDrive/Desktop/Rodhe/src/services/authService.js), lines 118–180.
- **Flaw**: The `resetPassword(identifier, newPassword)` function checks only if `identifier === 'rodhe'`. If true, it updates the database and local credentials with the new password.
- **Impact**: Any anonymous user visiting `/#admin`, clicking "Forgot Password?", and entering `rodhe` can permanently lock out the boutique owner.

### 2.4 High Vulnerability 4: Hardcoded Administrative Credentials in Client JavaScript
- **Source**: [`src/services/authService.js`](file:///c:/Users/VARUN%20THEJ/OneDrive/Desktop/Rodhe/src/services/authService.js), lines 9–15 and lines 83–86:
  ```javascript
  const isDefaultFallback = 
    (cleanId === 'rodhe' && cleanPass === 'rodhe@admin') ||
    (cleanId === 'admin@rodhe.in' && (cleanPass === 'WovenWithTrust2026!' || cleanPass === 'rodhe@admin'));
  ```
- **Finding**: The administrative credentials are embedded directly inside the compiled frontend bundle (`dist/assets/*.js`). Anyone running `strings` or searching the bundle can extract both passwords.

### 2.5 High Vulnerability 5: Forged Client Session Tokens
- **Source**: [`src/services/authService.js`](file:///c:/Users/VARUN%20THEJ/OneDrive/Desktop/Rodhe/src/services/authService.js), lines 67–68:
  ```javascript
  token: `rodhe_token_${Date.now()}`
  ```
- **Finding**: Session tokens are generated by simple JavaScript string concatenation on the client and stored in `localStorage`. They carry no cryptographic signature (HMAC) and are not validated by any backend service.

## 3. Threat Mitigation & Remediation Roadmap

1. **Migrate to Native Supabase Auth (`supabase.auth`)**:
   - Discontinue the custom `public.admin_users` table for authentication.
   - Provision the administrator inside Supabase Auth (`auth.users`), where passwords are encrypted using bcrypt and sessions are verified using cryptographically signed JWT tokens.
2. **Lock Down PostgreSQL RLS Policies**:
   - Revoke public `SELECT`, `UPDATE`, and `INSERT` policies on administrative tables.
   - Enforce `auth.role() = 'authenticated'` and bind permissions to an `app_metadata.role = 'admin'` claim.
3. **Secure Password Reset**:
   - Password resets must occur strictly via Supabase Auth's time-limited, email-verified magic link / OTP workflow (`supabase.auth.resetPasswordForEmail()`).
4. **Remove Hardcoded Credentials**:
   - Delete all hardcoded fallback usernames and passwords from client-side source code.
5. **Rotate Credentials Immediately**:
   - Because `rodhe@admin` and `WovenWithTrust2026!` have been stored in plaintext in the codebase, these passwords must be rotated immediately upon production deployment.
